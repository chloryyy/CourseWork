# ГОСТ 28147-89 (C++)

Программная реализация алгоритма криптографического преобразования данных
**ГОСТ 28147-89** на C++17. Реализованы все режимы стандарта:

1. **Простая замена** (ECB)
2. **Гаммирование** (счётчик / OFB-подобный режим)
3. **Гаммирование с обратной связью** (CFB)
4. **Выработка имитовставки** (MAC)

Реализация выполнена в объектно-ориентированном стиле и **не имеет внешних
зависимостей** — только стандартная библиотека C++.

## Структура проекта

```
├── gost_demo.vcxproj            проект демонстрации

```

## Сборка под Windows (Visual Studio)

Зависимостей подключать не нужно. Есть два равноценных способа.

### Способ 1. Готовое решение (двойной клик)

1. Открой `GostDemo.sln` двойным кликом.
2. Если Visual Studio предложит «обновить» (retarget) набор инструментов — согласись.
3. Выбери конфигурацию `Release` или `Debug`, платформу `x64`.
4. В обозревателе решений выбери стартовый проект:
   - `gost_demo` — интерактивная программа с меню;
   - `gost_tests` — прогон тест-векторов.
5. Нажми **F5** (запуск) или **Ctrl+F5** (запуск без отладчика). Программа
   показывает меню и не закрывается, пока не выберешь «Выход».

### Способ 2. CMake («Открыть папку»)

В Visual Studio: **Файл → Открыть → Папка…** и выбери каталог `gost28147`.
VS сама обнаружит `CMakeLists.txt`, сконфигурирует проект, и цели `gost_demo`
и `gost_tests` появятся в списке для запуска.

## Сборка через командную строку (CMake)

```sh
cmake -S . -B build
cmake --build build
./build/gost_demo      # интерактивная программа
ctest --test-dir build --output-on-failure   # тесты
```

## Интерактивная программа (`gost_demo`)

При запуске выводится меню (программа не закрывается до выбора «Выход»):

```
1) Ручной ввод (шифрование/дешифрование текста)
2) Работа с файлом (шифрование/дешифрование)
3) Прогнать встроенные тесты
0) Выход
```

- **Ручной ввод**: выбираешь действие (за-/расшифровать), режим, таблицу замен,
  ключ и синхропосылку. Текст вводится напрямую (поддерживается кириллица),
  шифртекст выводится/вводится в hex.
- **Работа с файлом**: те же параметры + пути входного и выходного файлов;
  данные обрабатываются побайтово (любой тип файла).
- **Встроенные тесты**: прогон тех же тест-векторов, что и в `gost_tests`.

Под Windows консоль автоматически переключается в UTF-8, поэтому русский текст
вводится и отображается корректно.

## API (кратко)

```cpp
#include "gost/gost28147.hpp"
#include "gost/modes.hpp"
#include "gost/substitution_table.hpp"

gost::Key key = /* 32 байта */;
gost::SubstitutionTable sbox =
    gost::SubstitutionTable::gost28147_CryptoProParamSetA();
gost::Gost28147 cipher(key, sbox);

// Простая замена (размер кратен 8 байтам)
gost::SimpleReplacement ecb(cipher);
auto ct = ecb.encrypt(plaintext);
auto pt = ecb.decrypt(ct);

// Гаммирование (произвольная длина), sync — синхропосылка (8 байт)
gost::Gamma gamma(cipher);
auto c = gamma.encrypt(data, sync);   // encrypt == decrypt

// Гаммирование с обратной связью
gost::GammaFeedback cfb(cipher);
auto c2 = cfb.encrypt(data, sync);
auto d2 = cfb.decrypt(c2, sync);

// Имитовставка (по умолчанию 4 байта = 32 бита)
gost::Mac mac(cipher);
auto tag = mac.compute(data, 4);
```

## Тестирование и корректность

Ядро шифра проверено на **официальных тест-векторах простой замены** из примеров
ГОСТ Р 34.11-94 (см. RFC 5831 / реализация OpenSSL ccgost). Для режимов
гаммирования, гаммирования с обратной связью и выработки имитовставки тест-векторы
получены независимой эталонной реализацией, сверенной с OpenSSL/CryptoPro, и
зафиксированы в `tests/test_gost.cpp`. Тесты также проверяют обратимость
(зашифрование → расшифрование).

## Замечания по реализации

- Блок и ключ интерпретируются в порядке little-endian; узел замен с номером `i`
  применяется к `i`-му 4-битовому блоку (блок 0 — младшие 4 бита).
- Основной шаг (раздел 3.2 методички): сложение с ключом по модулю 2³², замена по
  таблице, циклический сдвиг влево на 11, XOR со старшей половиной, сдвиг по цепочке.
- Базовые циклы (раздел 3.3): 32-З (зашифрование), 32-Р (расшифрование),
  16-З (имитовставка).
- Константы РГПЧ для гаммирования: к младшей половине прибавляется `0x01010101`
  (по модулю 2³²), к старшей — `0x01010104` (по модулю 2³²−1, с особым правилом
  ГОСТ для значения 2³²−1). Эти значения соответствуют стандарту и эталонным
  реализациям; в тексте методички (стр. 19) обе константы распознаны OCR одинаково.
